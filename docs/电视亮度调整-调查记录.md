## 2. 官方文档能查到什么（本次复核）

结论与既有探索记录一致：**官方公开文档没有任何亮度控制 API**。

| 文档 | 相关 API | 结论 |
|---|---|---|
| `03-API参考/应用与系统/SettingsService设置服务.md` | `luna://com.webos.settingsservice` 仅 `getSystemSettings`（读） | 只读；公开键只有 locale/country/audioGuidance/caption，**无亮度键**；ACG 组 `settings.query`（只读） |
| `02-开发指南/系统功能/屏幕保护程序.md` | Type 2 / Type 3 屏保 | 只会在闲置时**降低**亮度作为防烧屏策略（OLED webOS 5.0+），是系统行为，不是主动控制亮度的手段 |
| `03-API参考/媒体与数据/Audio音频.md` | `volumeUp` / `volumeDown` / `setMuted` | 音量有 +1/-1 步进方法（`volumeUp`/`volumeDown`）；**亮度没有任何类似方法** |
| ACG 文档（`访问控制组ACG.md`） | `settings.query` | 只给读权限，无写权限 |

**为什么音量可行、亮度不可行（既有记录已实机确认）**：
- 音量 `setVolume` 走 `audio.operation` 组，位于 `public.groups.json`，第三方 app 声明即生效；
- 亮度 `setSystemSettings` 走 `settings` / `settings.operation` 组，**不在** `public.groups.json`，app 声明无效（实测 `Denied method call`）。

## 3. 新发现：SSAP + createAlert 技巧（不需要 root）

### 3.1 为什么它能绕开 ACG

ACG 挡的是「**电视上安装的第三方 app** 以自身身份调 `settingsservice`」。
但 webOS TV 还有一个 **局域网控制协议 SSAP**（Smart Speaker API Protocol，webOS TV 2.0 起的远程控制协议）：
- 外部设备（电脑/手机/Home Assistant）通过 **WebSocket** 连电视（`wss://<tv-ip>:3001`，旧固件 `ws://<tv-ip>:3000`）；
- 配对后获得 `client-key`，之后免确认重连；
- 配对时声明的 manifest 权限里包含 **`WRITE_SETTINGS`** 与 **`WRITE_NOTIFICATION_ALERT`**（bscpylgtv `manifest.py` 已确认，该 manifest 沿用 LG 官方 `com.lge.test` 签名）。

**关键技巧（社区称 "proven workaround"，源自 bscpylgtv / ColorControl）**：
`setSystemSettings` 属于特权 luna 调用，SSAP 客户端直接调会被拒。
但可以通过 **通知弹窗 API** 间接执行：
1. `ssap://system.notifications/createAlert` 创建一个系统弹窗，弹窗的 **按钮 `onClick` / 关闭回调 `onclose` / 失败回调 `onfail`** 里带上 `luna://com.webos.settingsservice/setSystemSettings` 及其参数；
2. 立刻 `ssap://system.notifications/closeAlert` 关闭该弹窗；
3. **弹窗关闭动作由系统以系统级身份触发该 luna 调用** —— 从而绕过了 SSAP 客户端的权限限制。

bscpylgtv 源码原注释：
```python
# n.b. this is a hack which abuses the alert API
# to call the internal luna API which is otherwise
# not exposed through the websocket interface
# An important limitation is that any returned
# data is not accessible
```

### 3.2 具体协议与命令

**连接与配对**（bscpylgtv / LGforMac 一致）：
- `wss://192.168.1.4:3001`（新固件）或 `ws://192.168.1.4:3000`（旧固件）；
- 首连发 `register` 消息（manifest 见 bscpylgtv `manifest.py`），电视屏幕弹「允许此设备控制电视吗？」→ 用户确认 → 返回 `client-key` → 持久化复用；
- 之后所有请求是 `{"id": "<n>", "type": "request", "uri": "<ssap uri>", "payload": {...}}`，响应按 id 对应。

**读当前亮度**（可直接调，无需技巧）：
```
uri:  ssap://settings/getSystemSettings
payload: {"category": "picture", "keys": ["backlight"]}
响应: {"returnValue": true, "settings": {"backlight": 60}}
```
（LGforMac `TvController.swift` `readBacklight()` 原样实现；bscpylgtv `get_picture_settings` 默认键 `["contrast", "backlight", "brightness", "color"]`）

**写亮度（createAlert 技巧）**——LGforMac（Swift）实现：
```
step 1  uri:  ssap://system.notifications/createAlert
        payload: {
          "message": " ",
          "modal": true,
          "buttons": [{"label": "", "onClick": "luna://com.webos.settingsservice/setSystemSettings",
                       "params": {"category": "picture", "settings": {"backlight": "60"}}}],
          "onclose": {"uri": "luna://com.webos.settingsservice/setSystemSettings",
                      "params": {"category": "picture", "settings": {"backlight": "60"}}},
          "type": "confirm"
        }
        → 返回 {"returnValue": true, "alertId": "..."}

step 2  uri:  ssap://system.notifications/closeAlert
        payload: {"alertId": "<上一步返回的 alertId>"}
```

bscpylgtv（Python）实现（多加一个 `onfail` 增加冗余）：
```python
buttons = [{"label": "", "onClick": lunauri, "params": params}]
payload = {
    "message": " ",
    "buttons": buttons,
    "onclose": {"uri": lunauri, "params": params},
    "onfail": {"uri": lunauri, "params": params},
}
ret = await self.request(ep.CREATE_ALERT, payload)
alertId = ret.get("alertId")
return await self.request(ep.CLOSE_ALERT, payload={"alertId": alertId})
```

Home Assistant 自动化（lg-brightness-ha，LG G5 实测）用的是 `system.notifications/createAlert` + `closeAlert` + `settings/getSystemSettings` 读回验证，三处（button/onclose/onfail）都挂同一 luna 调用。

### 3.5 本机实测记录（2026-10-28，G6 实机验证 ✅）

**重要前提一：必须绑定源地址绕过 VPN**。本机到电视 `192.168.1.4` 的默认路由被 SecoClient VPN（172.16.1.x）劫持，直接连 3000/3001/9922 全不通；绑定本机物理网卡 `192.168.1.5` 后全部端口开放（详见 §9）。

**重要前提二：`com.lge.test` 共享签名已被 LG 加入黑名单**。bscpylgtv/LGforMac 用的签名 manifest 在本机注册被拒：
```json
{"type":"error","id":"register","error":"403 Pairing rejected: blacklisted certificate detected"}
```
**解法：改用无签名注册**（Home Assistant 的 aiowebostv 就是这么做的）——manifest 只带 `permissions` 列表（含 `WRITE_SETTINGS`、`WRITE_NOTIFICATION_ALERT`），不携带签名。

**完整握手流程（aiowebostv 同款，本机验证通过）**：
1. 连接：先 `ws://<ip>:3000`，失败回退 `wss://<ip>:3001`（本机实测 3000 被拒、3001 成功）；
2. 发 `{"id":"hello","type":"hello","payload":{}}` → 收到 `hello`（设备信息）；
3. 发 `ssap://system/getSystemInfo`（**新固件要求注册前获取**）；
4. 发 `register`（无签名）→ 电视弹「允许此设备控制电视吗？」→ 用户确认 → 返回 `client-key`；
5. 之后用 `client-key` 免确认重连。

**实测输出（原始记录）**：
```
[1] 当前 backlight = 60
[2] createAlert => returnValue=true alertId=com.webos.service.apiadapter.pub-...
[3] 写入后 backlight = 45 => ✅ 写入生效
[4] 恢复后 backlight = 60 => ✅ 已恢复

[0] 当前 backlight = 60
[+1] 目标=61 读回=61 => ✅
[-1] 目标=60 读回=60 => ✅
```

### 3.4 局限与注意事项

1. **写操作无返回值**：createAlert 触发的 luna 调用结果拿不到（bscpylgtv 注释明确）。**必须写后 `getSystemSettings` 读回验证**——社区所有实现都是这么做的。
2. **可能闪 OSD**：createAlert→closeAlert 会创建又立刻关闭一个系统弹窗，屏幕上可能一闪而过；用空 message、空 label、`modal: true` 尽量隐形。实测（lg-brightness-ha）未报告可见弹窗残留。
3. **需要电视网络控制开启**：「LG Connect Apps / 网络控制」默认开启（新机型），LGforMac README 要求 "network/mobile control enabled"。
4. **固件差异**：3000 还是 3001、`modal`/`type` 参数是否需要，各固件略有差异；LGforMac 用 3001 优先、3000 回退。
5. **亮度键名因机型而异**（见 §5），写之前先读确认。

## 4. 「亮度 +1/-1」如何实现

**结论：webOS 没有亮度步进 API，也没有亮度按键事件可模拟。** 音量有 `volumeUp`/`volumeDown`，亮度没有对应物（bscpylgtv `buttons.py` 全量按键表已确认：无 `BRIGHTNESS_UP/DOWN`）。

因此「+1/-1 调整到目标亮度」的通用实现模式是 **读当前值 → 计算目标值 → 直接写目标值**：

```
cur = getSystemSettings(picture, backlight)     # 读当前亮度（SSAP 直读，或 root 下 luna-send 读）
target = clamp(cur + delta, 0, 100)             # delta = +1 / -1 / 任意步长
setSystemSettings(picture, backlight=target)    # 写（SSAP createAlert 技巧，或 root 下 luna-send 写）
verify = getSystemSettings(picture, backlight)  # 读回验证
```

- **不需要 root 的版本**：用 §3 的 SSAP createAlert 写 + SSAP 直读。**本机 G6 已实测 ✅**（60→61→60，见 §3.5）。
- **root 版本**：[webos-adjust-backlight](https://github.com/stamminator/webos-adjust-backlight) 就是此模式（`luna-send` 读 → 算 → `luna-send` 写，支持 up/down 与步长），配合 LG Input Hook 绑到遥控器按键上。
- 社区亮度滑条应用（LGforMac/LGforWin）也是「读当前值定位滑条 → 拖动防抖后写目标值」。

> **实测备注**：`backlight` 值类型是**字符串**（如 `"60"`），读写时保持字符串格式。

## 7. 本机实测步骤（2026-10-28 已完成 ✅）

实测已在 G6 上完成（直接设置 + 步进均成功，见 §3.5）。以下为**可复现的操作步骤**，供后续部署程序参考：

1. **确认电视在线**（绑定源地址）：`Test-NetConnection 192.168.1.4 -Port 3001`（SSAP）与 `-Port 9922`（SSH），**必须用绑定 `192.168.1.5` 的方式**（见 §9）。
2. **SSAP 配对**（仅首次需要遥控器确认）：
   - WebSocket 连 `wss://192.168.1.4:3001`（绑定源地址）；
   - 发 `hello` → 发 `ssap://system/getSystemInfo` → 发 `register`（**无签名** manifest，permissions 含 `WRITE_SETTINGS` / `WRITE_NOTIFICATION_ALERT`）；
   - 电视弹「允许此设备控制电视吗？」→ 遥控器确认 → 保存 `client-key`（本机已存：`34c3832d96106a640be28d2096d8c819`）。
3. **读亮度**：`ssap://settings/getSystemSettings` + `{"category":"picture","keys":["backlight"]}`。
4. **写亮度**：`ssap://system.notifications/createAlert`（message 空格 + buttons/onclose/onfail 挂 `luna://com.webos.settingsservice/setSystemSettings` + params）→ 取 `alertId` → `ssap://system.notifications/closeAlert`。
5. **步进**：读当前值 → ±1（或任意步长）→ 写 → 读回验证。
6. **验证**：写后读回一致；电视重启/待机恢复后亮度保持（属于用户设置的一部分，会持久化）。

> **注意**：prisoner/SSH 身份读 picture 类别仍 `Access denied`（ACG 限制），SSAP 路径不受影响。

## 9. 网络绕行：绑定源地址绕过 VPN（实测必须）

本机实测时发现：到 `192.168.1.4` 的默认路由被 **SecoClient VPN（172.16.1.121 / 以太网 2）** 劫持，导致：
- 直接 `Test-NetConnection 192.168.1.4 -Port 3000/3001/9922` 全 **CLOSED**（流量进了 VPN）；
- `Find-NetRoute -RemoteIPAddress 192.168.1.4` 显示走 `以太网 2`（VPN 网卡）；
- 甚至 ARP 表中 `192.168.1.4` 出现两个 MAC（VPN 虚拟 MAC `00-FF-EC-6D-71-C5` 与电视真实 MAC `8C-77-79-46-02-90`）。

**解法（与既有 SSH 调试指南一致）**：绑定本机物理以太网卡 `192.168.1.5` 作为源地址：
- PowerShell 端口测试：`TcpClient.Client.Bind(IPEndPoint('192.168.1.5'))` 后再 `Connect`；
- Node.js `ws` 库：`new WebSocket(url, { localAddress: '192.168.1.5' })`；
- SSH：`ssh -b 192.168.1.5 ...`。

绑定后电视 3000/3001/9922/9998 全部开放，SSAP 实测成功。
